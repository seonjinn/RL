# Qwen3-8B GBS512 /32K frozen correctness gate

User-approved follow-up to the GBS8/OSL1024 200-step online-cadence study.
This does not extend or overwrite those runs and does not fix checkpoint resume.

GBS is the total sample count, not the engine's concurrent request count. Baseline
uses engine-derived limits and graph buckets; this does not mean unlimited
concurrency. The default-baseline versus S8 SpecDec comparison includes runtime
tuning and cannot isolate the speculative algorithm alone. Record actual engine
limits, peak KV use/preemption, lengths, truncation and repetitions. No minimum
output length or target rollout share is forced.

The previous GBS128 gates failed because the positive logprob chunk size lacked
defer_fp32_logits=true. The actual setup validator is now exercised on fully
resolved configs in a CPU test, in addition to launcher-contract regressions.
Existing eleven-arm GBS8 200-step rendering and resume-check settings are retained.

Before expansion require three successful policy steps, generation/refit/logprob/
training diagnostics, finite rewards and KL metrics, output inspection, and
memory/CUDA Graph validation. Passing frozen gates does not validate online
updates or checkpoint resume. Do not submit1000-step runs based on this gate alone.

Submission uses immutable source bundles, archived submodule pins and the same
Aug18 nightly image as the previous Q8 study. No image/version bump is included.
