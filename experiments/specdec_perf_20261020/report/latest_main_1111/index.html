Drafter provenance. Both Qwen3.5 drafters are public community checkpoints, not NVIDIA releases: DFlash z-lab/Qwen3.5-35B-A3B-DFlash (BF16, block 16) and DSpark jinzex/Qwen3.5-35B-A3B-DSpark (BF16, block 8). Both were trained against the Instruct model, but the GRPO target here is the Base model. This mismatch explains the lower acceptance length (about 3.2 at block-size K vs about 5 in standalone vLLM validation on Instruct).

Reading the numbers

  • Generation is the only stage SpecDec changes. Policy training, LogProb and Refit stay within run noise (0.97x-1.03x) for Qwen3-30B-A3B. Every E2E gain comes from generation time.
  • Qwen3-30B-A3B: generation gets 1.72x (DFlash) and 1.64x (DSpark). Generation is only 38% of the baseline step, so E2E gets 1.19x and 1.17x.
  • Nemotron 3.5 Nano: generation gets only 1.14x / 1.14x, and acceptance lengths are lower (3.33 / 3.96). The DSpark drafter is the public NVFP4 checkpoint because the BF16 repo is private. The hybrid Mamba target runs without prefix caching. DFlash LogProb and Refit look 0.89x, a single-run difference that needs a repeat before it counts.
  • SWE RL: model calls run 2.0x faster with either drafter, but model calls are only part of each trajectory (tool runs, agent overhead and final eval stay the same). Exposed generation gets 1.37-1.42x and the E2E step gets 1.23-1.25x.
  • Qwen3.5-35B-A3B: SpecDec at block-size K is slower. vLLM holds 1+K Gated DeltaNet state blocks per request, which cuts the batch it can run, and DFlash adds per-step KV-group metadata cost. The same slowdown (DFlash K7 gen 0.61x) showed in the October cohort, so this is a vLLM hybrid-model limit, not a regression. Small K partly fixes it: DSpark K4 reaches 1.28x generation, but DFlash K3 stays at 0.77x, and E2E is flat at best.
  • Single run per arm. No confidence intervals on this page.
