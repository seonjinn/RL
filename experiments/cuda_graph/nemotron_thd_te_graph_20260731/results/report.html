The runs used the same prompts, config, and seed, but sampled rollout tokens already differed at step 1. One repeat therefore cannot establish a convergence effect; the step-20 result is a correctness warning that requires fixed-rollout parity and repeated runs.

Root-cause status

  • Confirmed performance cause: NeMo-RL calls _reset_te_cuda_graph_banks_for_storage_relocation() whenever it enters the reference-model weight-swap context. In this BF16 run that discards the captured bank every optimizer step. Telemetry confirms capture=1 and cache-hit=0 on every measured step.
  • Correctness boundary: get_logprobs() explicitly uninstalls TE graph replay and computes prev-logprobs eagerly. The step-18 mismatch therefore existed before that step's graph training replay. It can still be a downstream effect of earlier graphed updates or refit, so graph correctness is not cleared.
  • Next gate: preserve graph banks only when reference-weight restoration is demonstrably address-stable, then run an identical-batch eager-vs-graph output/gradient parity test before another performance claim.
