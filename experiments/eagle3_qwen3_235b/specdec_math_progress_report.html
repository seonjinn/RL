500K Parallel Plan

Short Answer

Yes, generate hidden states in parallel first, then train once on the full cache. One correction is required before launch: the raw 500K 30B response set has 59 duplicate normalized prompts, so the exact-unique path should dedupe or add 59 replacements first.

Proposed split
20 shards

25K samples per shard, each using 1 node / 4 GPUs for vLLM hidden-state extraction.

Fast path resource
80 GPUs

If scheduled together, hidden-state extraction could finish in a few hours instead of serial multi-day chunks.

Parallel Flow

Merge 10x50K

Create one conversation JSONL and enforce normalized-prompt uniqueness.

Prepare once

Build one 500K Arrow dataset.

Shard hidden states

Run global ranges: 0-25K, 25K-50K, ...

Train once

Train Eagle3 on the complete unique hidden-state cache.

Evaluate

Run NeMo-RL baseline vs K=1/K=2/K=3.

Tradeoff

OptionProsCons
Serial 50K continuation Lower storage pressure; already running. Slow to reach 500K.
Parallel 500K full cache Fastest way to test a true 500K drafter. Needs many GPUs and roughly 30TB if all hidden states are retained.
