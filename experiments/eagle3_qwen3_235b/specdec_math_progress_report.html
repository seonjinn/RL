Training Data Rationale

The 500k target is aligned with public Eagle3/speculator practice rather than being arbitrary. The NVIDIA Qwen3-235B-A22B-Eagle3 model card reports 503.3K training data points from two prompt sources, UltraChat-200k and Magpie-Llama-3.1-Pro-300K-Filtered, with target responses synthesized by Qwen3-235B-A22B. The Red Hat Qwen3-235B-A22B-Instruct-2507 speculator similarly reports training with the Speculators library on Magpie plus UltraChat. The vLLM Speculators training docs define the same three-stage pipeline used here: target hidden-state generation, vocab mapping, then Eagle3 training. For RL deployment, the long-tail gate follows the design pressure described in TLT / Adaptive Drafter: SpecDec is most useful during low-effective-batch long-tail rollout, while large active batches can lose throughput. Current 235B K=1/K=2 jobs therefore gate on scheduled requests ≤32 and scheduled tokens ≤2048 with CUDA graph still enabled.

Reference Training Data Scale

Public EAGLE3/SpecForge references consistently use hundreds of thousands to more than one million generated target responses, not just 50k. For this project, 50k and 100k are sanity checkpoints; the practical target remains a unique mixed-math pool near 500k before judging whether acceptance has saturated. OpenMath-only remains useful for a controlled in-domain sanity check, but it is not a fair final train/test split for NeMo-RL math.
