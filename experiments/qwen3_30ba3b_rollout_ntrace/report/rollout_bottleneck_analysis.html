Its 133.63 s idle interval may come from rollout orchestration, request availability, or the profiler boundary. The GPU trace alone cannot decide.

What this says about the adaptive linear work

This recipe quantizes only routed expert FC1 and FC2. QKVO, attention, the MLP gate, and lm_head stay BF16. The measured MXFP8 work therefore runs through the FlashInfer TRTLLM MoE grouped-BMM backend. A dense-linear tactic lookup does not optimize this recipe unless the quantization scope is expanded to dense projections. Expert FC1/FC2 tactic selection is the relevant kernel-tuning path here.

Evidence and limitation

  • About 17.3M measured replay rows and 28.8K-30.2K unique replay nodes per rank.
  • Zero uncovered replay nodes across ranks 0-7; all nodes map to captured graph clones.
  • Rank active-time max/min spread is 2.7%, so worker compute skew is small.
  • The trace saved successfully before a post-save Ray finalizer error.
No matched BF16 speedup claim is made here.
The BF16 control failed before generation because Qwen sparse refit tried to copy a 2D expert W2 tensor into a 3D vLLM destination. A generation-only BF16 control or a Qwen-compatible sparse-refit conversion is still required.
