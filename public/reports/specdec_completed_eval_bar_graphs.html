Current Interpretation

The newest Qwen3-8B long-rollout data strongly implicates the runtime scheduler gate. With the TLT-style gate, K=1/K=2/K=3 Step 1 generation is only about 1.035-1.041x, and the latest gated points remain modest through Step 5/8. When the gate is disabled, K=1 generation is 1.373-1.458x and K=3 generation is 1.433-1.578x through Step 4. E2E improves to 1.163-1.196x for K=1 and 1.204-1.253x for K=3 through Step 4.

This is not the whole story. The short512 and r22 exact-engine/no-gate diagnostics show K=1 can help in NeMo-RL (1.278-1.299x generation, 64.61% acceptance), while K=3 can regress badly under the same fixed 512-token greedy shape (0.423-0.452x, 40.66% acceptance). That points to both gate behavior and K/workload fit, not BF16 vs FP8, as the main variables.

Qwen3-32B now shows the same gate pattern. Gated K=1/K=2/K=3 all completed 20 steps and remain below baseline on average. Always-on K=1/K=3 improves generation to 1.331-1.430x and E2E to 1.149-1.196x through Step 4. K=2 always-on failed before aggregate rollout metrics under high KV-cache pressure, so it is not counted.

Gate metrics confirm the code-level mechanism: with request threshold 8 and token threshold 4096, scheduler lookahead is enabled only about 0.03-0.04% of observed 8B gated decisions and about 0.23-0.27% of observed 32B gated decisions. Runner-side draft generation is also only about 1-4% active. The gated runs are therefore mostly baseline decoding with a small long-tail SpecDec tail.

Latest exact-engine status: r22 emitted the key generation-only metrics. Baseline 3126355 reached 5652.52 generated tok/s/GPU. Native K=1 3126356 reached 7345.13 generated tok/s/GPU, giving 1.299x generation speedup with 64.61% acceptance. Native K=3 3126357 reached 2555.29 generated tok/s/GPU, giving 0.452x with 40.66% acceptance and per-position acceptance 61.05%, 38.46%, 22.27%. Dynamic-cap r24 3126685 used a K=3 engine with scheduler effective_k=1 and reached 4446.23 tok/s/GPU, or 0.787x vs the exact-engine baseline, despite 64.60% acceptance. This shows native K=1 is materially better than simulating K=1 through a K=3 dynamic-cap engine in the current code path.

New isolation axis: Qwen3-8B vLLM standalone DAPOMath real-prompt bs32 retry2 completed after tokenizer fallbacks were patched. The result is a regression for every K: K=1 0.665x with 61.11% acceptance, K=2 0.817x with 46.91% acceptance, and K=3 0.853x with 36.62% acceptance. This means the synthetic fixed-prompt standalone 2x speedup is not representative of the real DAPOMath prompt distribution.
