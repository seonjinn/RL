Building DFlash Drafters for Qwen3-235B

Everything that goes into our speculative-decoding drafters: the datasets (with train/test separation guarantees), the software stack, the training configuration, and the wall-clock relay that fits multi-day training into 4-hour queue slots. Companion pages: overhead & SpecDec study, init/framework fixes.

The source mix contains 850,220 rows, but prepare_data.py --max-samples 850000 shuffled and selected exactly 850,000 physical Arrow rows. The saved dataset_info.json retained the stale 850,220 source count. Direct Arrow record-batch counts and the producer command are authoritative for training.

Train/test separation (three walls, all enforced in code): (1) instance wall — evaluation = 3 astropy SWE-bench_Verified instances (12907/13236/13398); the training pool = 7 disjoint instances (django×4, sympy, sphinx, requests); (2) content wall — any public-SWE conversation that even mentions "astropy" is dropped (827 dropped); (3) fingerprint gate — the final 850K corpus is scanned for the eval instance IDs, distinctive problem-statement phrases, and the OpenHands system prompt before training may start (result: 0 hits). The gate is not theoretical: it caught a real contamination accident (a dataset-builder bug had stamped astropy's task payload into 1,680 pool rows) and blocked it from entering training.

3. Software stack

AWS-DFW GB200 (aarch64), 2 nodes per training job ┌────────────────────────────────────┐ ┌──────────────────────────────────────┐ │ Node 0 — target server │ │ Node 1 — drafter training │ │ vLLM 0.25.x (vllm_venv, uv py3.12) │ │ speculators @ repo HEAD (editable) │ │ Qwen3-235B-A22B-Thinking, TP=4 │──▶│ + hs_connectors sub-package │ │ --target-layer-ids 1 23 46 68 91 │ │ torchrun --nproc_per_node 4 │ │ hidden-state KV-connector ────────▶│ │ FileBackend reads from lustre cache │ │ --hidden-states-path (lustre) │ │ --vllm-endpoint http://node0:8000/v1 │ └────────────────────────────────────┘ └──────────────────────────────────────┘
  • Trainer: vllm-project/speculators installed editable from the repo (scripts/train.py + scripts/prepare_data.py); the PyPI release lags the repo scripts.
  • Online mode (--on-missing generate --on-generate delete): the target runs one-token decode on each already-tokenized conversation to expose verifier hidden states through a shared-filesystem connector. It does not replace the stored assistant response. Generated hidden-state files are deleted after use; offline caching would have needed 24–40 TB.
  • Cross-node: training connects to the server via --vllm-endpoint; hidden-state files transit a lustre path visible to both nodes.
  • Cluster plumbing: CUDA_HOME=/cm/shared/apps/cuda13.0/toolkit/13.0.2 + ninja/cmake in the venv (GB200 sm_100 JIT), TMPDIR=/tmp (ZMQ 107-char limit), system-forced HF_HUB_CACHE on the project share.
  • Drafter checkpoints are speculators-format (DFlashDraftModel) — loaded directly by vLLM 0.25 speculative_config with no conversion; shipped between clusters via PBSS S3 (~1 min for 4 GB).

4.1 The wall-clock relay (how 26+ hours fit in 4-hour queue slots)

sbatch chain (interactive QoS, starts in seconds; batch_long queue waits hours): c1 ──afterany──▶ c2 ──▶ c3 ──▶ … ──▶ c8 ──afterany──▶ batch_long finisher (40h) each chunk: same sbatch, same --save-path → trainer auto-resumes (epoch + mid-epoch step skip from training_state.json; optimizer/scheduler restored) finished early? remaining chunks boot, see "nothing to train", exit in minutes (idempotent)

Chunks are wall-time, not data: the total sample count is fixed by (unique samples × epochs) — v2 trains 1,700,440 passes whether it takes 5 chunks or 8.

5. Evaluation methodology

  • During training: per-epoch validation reports EAL (expected acceptance length = Σk P(first k draft tokens all accepted)) and per-position acceptance. Useful for screening, but only comparable within one val distribution — we measured a drafter with val EAL 3.27 (100% SWE-smith) that was slower on real rollouts than one at 1.86.
  • The real scoreboard: NemoGym SWE2 rollouts (OpenHands agent, apptainer per instance, vLLM 0.25, K=5) on the held-out astropy instances — tok/s = completion tokens ÷ model-call time.
  • Contamination scans accompany every claim: v1's 1.33× was backed by scanning all 628,540 training rows for eval fingerprints (0 hits).

6. Held-out SWE rollout result

V2 passes the rollout gate. On the same three held-out astropy instances and the same K=5 harness, V2 delivered 133.21 completion tok/s: +52.4% over non-speculative decoding and +15.0% over v1. Throughput uses the same trajectory-weighted formula for every row: Σ completion tokens ÷ Σ model-call seconds. Per-token model time fell from 11.44 ms (baseline) to 8.63 ms (v1) to 7.51 ms (v2), a 34.4% reduction from baseline and 13.0% from v1. The three stochastic trajectories generated different token counts, so this small smoke set establishes a strong performance signal, not a confidence interval or a quality comparison. Speculative acceptance counters were not serialized by this logger and are therefore reported as not collected, rather than inferred.

K=7 is rejected. It reached only 94.68 tok/s: 8.3% above baseline, 18.3% below v1 K=5, and 28.9% below v2 K=5. The K=7 capture sizes [8,16,32,64,128] were captured successfully, so the result is not explained by a missing graph bucket. vLLM did warn that the speculative settings limited max_num_scheduled_tokens to 1280 and that first-inference Triton kernels were JIT-compiled. Because acceptance counters were not serialized and the smoke contains only three stochastic trajectories, the safe conclusion is operational: K=7 does not pass the deployment gate; K=5 remains the measured optimum. A larger warm-cache matched repeat is needed before attributing the full regression to acceptance decay versus runtime scheduling.

8.1 What the implementation audit corrected

  • 850,220 is not the physical training row count. dataset_info.json retained the pre-selection source metadata 850,220, but direct Arrow IPC record-batch counting gives exactly 850,000 rows. The original producer also used --max-samples 850000. Launch validation now requires both facts: 850,000 is the physical authority, while the stale 850,220 value is separately hashed and retained as provenance.
  • The actual train/validation split is row-based, not shard-based. Speculators uses B=int(N*0.9), so the frozen v2 data is split into 765,000 train rows and 85,000 validation rows. The boundary falls inside Arrow shard 9. The rejected first implementation incorrectly assigned entire Arrow files to train or validation.
  • Smoke rows now preserve production membership. Each 128-row smoke is constructed from production rows [0,115) plus [B,B+13), rather than taking a 128-row prefix whose validation examples would actually belong to the production training range. Finalization replays those parent selections and compares the vocabulary/token-frequency artifacts byte-for-byte.
  • --on-missing generate does not regenerate responses. The live Speculators client sends the already-tokenized full conversation with max_tokens=1 to collect hidden states. Therefore the Open-SWE Minimax/Qwen3.5 assistant/tool trajectories are real training targets, and source-model plus scaffold provenance must be reported. The earlier statement that “only prompts matter” was incorrect.
  • Open-SWE cannot be loaded with a default config and train split. The reviewed public path pins config openhands and the two published splits minimax_m25 and qwen35_122b, whose rows use trajectory rather than conversations.
  • The 18.3 GB source must not be materialized on the login node. The first read-only streaming probe ended in a login-node MemoryError. The production selector now stores canonical payloads in a disk-backed SQLite spool and runs only in the scheduled CPU job.

8.2 Fail-closed gates added after independent review

  • The manifest builder writes a non-launchable staged report. Only the finalizer can produce status=pass, after recomputing 100K row counts, manifest SHA256, token mass, held-out hits, DF-HARD per-instance cap, and every selected smoke/full prepared artifact.
  • The artifact commitment binds every regular file, ordered state.json Arrow shards, physical row counts, the exact 0.9 row split algorithm, target schema, and patched Speculators commit. Root or child symlinks and mid-hash mutation are rejected.
  • The submit wrapper verifies the live AWS scheduler hostname aws-dfw-cs-001-login-01.cm.cluster before even running scheduler preflight. The user-facing SSH alias remains aws-dfw-cs-001-login-01.nvidia.com.
  • vLLM readiness timeout now performs bounded TERM/poll/KILL/reap cleanup. After readiness, the launcher watches both vLLM and training; a server-caused failure stops training promptly and preserves the server exit status.
  • Status collection uses one bounded SSH command, strict JSON/base64 framing that raw logs cannot forge, atomic JSON/Markdown outputs, and a hard 200-line-per-job remote-output budget.
