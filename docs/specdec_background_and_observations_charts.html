Core Message

Acceptance rate is necessary, but it is not sufficient. SpecDec helps only when accepted draft tokens save more target-model work than the added drafter, verification, rejection sampling, scheduler, cache, and CUDA Graph overhead. This is why the Figure 4-style breakdown in arXiv 2601.11580v2 is the right lens: separate drafting, verification, rejection sampling, and other vLLM overheads before claiming a speedup.

Acceptance Rate Projection

K=1 ideal upper bound is approximately 1 + acceptance. Our best 30B K=1 run gives an overhead efficiency of about 0.64, so a practical same-regime estimate is 1 + 0.64 * acceptance.

Recommended Next Actions

  1. Produce a Figure 4-style vLLM timing breakdown: drafting, verification, rejection sampling, and other overheads.
  2. Keep CUDA Graph enabled for performance runs.
  3. Use load-aware gating instead of always-on SpecDec: active requests, scheduled tokens, and per-position acceptance should all matter.
  4. Prefer K=1/K=2 until later-position acceptance supports K=3.
  5. Report generation speedup and E2E speedup separately for every NeMo-RL run.
