Background

Beginner background

Target policy rollout produces trajectories; a draft policy proposes tokens; refit updates the draft from the latest policy behavior.

Version identifies the policy and draft checkpoint pair used for a rollout. Runtime means the vLLM environment and execution settings used to measure that pair.

Integration: A non-PR integration branch will combine reviewed heads for the Qwen3-8B DFlash and DSpark matrix.

Branch: seonjinn/draft-cotrain-integration-20260818; status: planning.

Intuition

For Qwen3-8B, a stale draft still predicts tokens from an earlier policy while RL has shifted the target distribution. Co-training shortens that gap: the policy rollout feeds refit, and the refreshed draft proposes against the next target-policy version.

The goal is not a claimed speedup before measurement; it is a controlled comparison of stale and co-trained draft flows under the same runtime.

Review quiz

  1. Why does DraftStepState retain raw draft numerators and counts until step finalization?

    Invariant: The invariant is that draft normalization uses globally reduced draft bins, independent of microbatch partitioning.

  2. How many DFlash queries are constructed for a block width gamma?

    Invariant: The invariant is that DFlash has one anchor-conditioning query plus gamma mask queries, while only gamma emitted tokens contribute to loss.

  3. What makes DFlash anchor selection reproducible in split training?

    Invariant: The invariant is that anchor plans depend on stable sample identity rather than local microbatch order.

  4. When may NCCL refit transfer a draft tensor directly?

    Invariant: The invariant is that direct transfer is limited to stable exact-layout live storage; loader transformations use the misc path.

  5. What must a DFlash or DSpark performance claim include?

    Invariant: The invariant is that performance claims include refit-inclusive end-to-end measurements under a matched matrix.
