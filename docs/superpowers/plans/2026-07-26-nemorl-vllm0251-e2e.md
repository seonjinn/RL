# NeMo-RL vLLM 0.25.1 E2E Benchmark Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a gated Qwen3-30B-A3B Math GRPO experiment that proves the NeMo-RL generation workers use vLLM 0.25.1 and compares baseline, Eagle3, DFlash, and DSpark with matched E2E metrics.

**Architecture:** A focused experiment package owns a typed matrix contract, runtime/checkpoint preflight, a Lyris wrapper around the existing low-level NeMo-RL submission script, and a result collector that reuses the repository's full-GRPO parser. Local tests exercise all rendering and classification logic without SSH or GPUs; remote work is allowed only after the version and smoke gates pass.

**Tech Stack:** Python 3.12+, PyYAML, Bash, pytest, NeMo-RL, Ray, vLLM 0.25.1, SLURM, Lyris GB200

## Global Constraints

- Target model is exactly `Qwen/Qwen3-30B-A3B`.
- Workload is the existing Qwen3-30B-A3B Math synchronous GRPO performance recipe.
- Sampling is `temperature=1.0`, `top_p=1.0`, and `top_k=-1`.
- Smoke runs complete one GRPO step; measurement runs complete ten GRPO steps.
- Runtime must be exactly `vllm==0.25.1` in both the driver and generation-worker Python environments.
- Methods are baseline, Eagle3 K3, DFlash, and DSpark.
- DFlash and DSpark checkpoint paths and K values are explicit inputs; missing selected checkpoints block submission.
- All measured methods use identical target model, recipe, topology, precision, batching, prompt set, and generation length.
- SpecDec uses `enforce_eager=false`, FULL CUDA Graph mode, and explicit `(K+1)`-multiple capture sizes through `max_num_seqs * (K+1)`.
- `max_cudagraph_capture_size` is forbidden.
- The launcher defaults to dry-run and requires `SUBMIT=true` for state-changing submission.
- Partial, failed, or rollout-only rows never contribute to E2E speedup calculations.
- Preserve all unrelated dirty-worktree changes and commit only files owned by this experiment.

class ContractError(ValueError):
    pass


def derive_capture_sizes(max_num_seqs: int, k: int) -> list[int]:
    if max_num_seqs <= 0 or k <= 0:
        raise ContractError("max_num_seqs and k must be positive")
    stride = k + 1
    return list(range(stride, max_num_seqs * stride + 1, stride))

@dataclass(frozen=True)
class RuntimeProbe:
    role: str
    vllm_version: str

    ray_version: str
    machine: str


def current_runtime_probe(role: str) -> RuntimeProbe:

    import ray
    import vllm

        role=role,

**Interfaces:**
- Consumes only methods with passing one-step smoke gates.
- Produces matched generation and full E2E speedups over steps 2–10.

- [ ] **Step 1: Submit the measurement matrix**

Use `STAGE=measurement SUBMIT=true` with baseline plus every passing SpecDec
method.

Expected: the wrapper rejects any method without a passing smoke gate.

- [ ] **Step 2: Monitor every job for five minutes**

Record job state and the first fatal marker in each manifest.

- [ ] **Step 3: Collect terminal results**

Run `collect_results.py` against the measurement job CSV and log roots.

Expected: step, summary, comparison, and JSON report artifacts are created.

- [ ] **Step 4: Validate comparison eligibility**

Confirm the baseline and each reported variant have identical comparison keys,
runtime provenance, completed step windows, and no fatal errors.

Expected: invalid pairs have empty speedup fields and an explicit mismatch
reason.

- [ ] **Step 5: Report the result**

Present generation throughput/time speedups and E2E throughput/step-time
speedups separately. Label DSpark as blocked rather than measured when no new
checkpoint was available.
