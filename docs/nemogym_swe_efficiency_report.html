NeMo-RL + NeMo-Gym SWE Rollouts: Overhead Analysis & Speculative Decoding Study

Measurement stack: NVIDIA-NeMo/RL PR #3243 (rollout-only eval mode) + Gym PR #1825 / nv-OpenHands PR #19 (rollout timeline profiler). Environment: Lyris GB200 (1 node, 4 GPUs), vLLM 0.25.1, Qwen3-30B-A3B-Thinking-2507 (TP2 × 2 engines), Gym latest main (fbde772), nv-OpenHands sdd/multilingual-fixes@5f018005. Workloads: SWE1-pivot (single-step, 400 rollouts) and SWE2 (OpenHands agentic SWE-bench_Verified, 3 instances × ≤8 turns, temperature 1.0). Performance statements are labeled Measured (committed raw artifact), Handoff-reported (reported without a committed raw artifact), or Projected (a cost model or unvalidated hypothesis).

Executive summary. (1) Measured: the n=24 paired ledger shows that the patch lowers phase sum from 127.4 to 123.6 s/rollout. The stable savings are connect/action-server (3.9 s) and framework/run-infer (5.4 s), while initialization changes only 0.3 s. Workspace initialization is dominated by a cross-filesystem full-copy fallback, not git cleanup: cp -al cannot hard-link from the read-only instance squashfs to the writable workspace filesystem, so it falls back to cp -r. NRL_SKIP_GIT_RESET=1 changed initialization only from 20.1 to 19.9 s. (2) For speculative decoding, off-the-shelf model-free drafters (Suffix, N-gram) lose at every setting on this workload, EAGLE-3 only wins at K=1 (+4%), and DFlash at K=7–9 is the clear winner: 309–310 tok/s = 1.48× over the 209 tok/s baseline, using a parallel one-pass draft and a 4K drafter context window. (3) Projected: from the 123.6-second patched phase model, removing the identified approximately 45 seconds gives a 78.6-second realistic bound (1.57×); removing all 49.3 seconds of connect + initialize + framework gives the 74.3-second zero-overhead bound (1.66×). Neither is an observed job-wall result. See the detailed initialization and framework analysis for code paths and validation gates. (4) The compact trial summary classifies the null, invalid, design-rejected, and deferred experiments so that none is treated as a validated optimization.

Winner: DFlash K7–K9 at 1.48×. It is the only method that simultaneously avoids all three measured failure modes: it drafts in one parallel pass (no K sequential drafter forwards), it is model-based (better acceptance than lookup), and its drafter runs with a 4K context cap (speculative_config.max_model_len=4096), which sidesteps the long-context collapse below. It keeps vLLM async scheduling (it is grouped with the EAGLE model types) and ran with FULL CUDA graphs captured at (K+1)-multiple sizes. Notably this used the generic RedHatAI/Qwen3-30B-A3B-speculator.dflash drafter — not even matched to the Thinking-2507 target — so there is further headroom with a matched drafter. K=16 over-drafts (250 tok/s); the optimum sits near K≈7–9.

The EAGLE-3 drafter (trained on short instruction-response data) is out-of-distribution beyond ~8K context: past 16K it accepts almost nothing (MAL 1.05–1.07), far below the K=3 break-even (~1.6–1.8). This explains the measured 0.90× at K=3. At K=1 the position-1 acceptance (26%, MAL ≈ 1.26) clears the minimal cost of one drafter forward plus a 2-token verify, yielding the small +4% win. The same drafter reaches 64.8% acceptance (MAL 2.94) and 1.63× generation speedup on short-context math GRPO on this exact stack — the workload, not the stack, is decisive.

2.3 Why model-free drafters fail: proposal cost scales with context

Suffix and N-gram keep healthy, context-stable acceptance (table above) but still lose end-to-end at every K: suffix builds/walks its tree over the 16–33K-token context per request, and N-gram scans the prompt every decode step. Confound checks all passed: a V1-piecewise no-spec baseline measured 209 tok/s — identical to the V2 FULL-graph baseline at this concurrency (BS 1–2), so CUDA-graph configuration was not the cause; replaying with the ISSTA'26 paper's exact adaptive setting (Kmax=32, match-length-proportional budget) still lost (115 tok/s). The 1.66–3.35× suffix speedups reported by that paper on SWE-bench come from greedy decoding, thinking-mode disabled, and a slow vLLM v0.12 baseline — none of which transfer to RL rollouts (temperature 1.0, Thinking policy). Their finding that EAGLE-3 loses on SWE-bench (0.70–1.10×) matches ours.

2.4 Prefix cache: 0% hits in both workloads

Despite enable_prefix_caching=True, measured cache hits are zero across 400 SWE1 rollouts and all SWE2 turns. Two mechanisms, one root: (a) in SWE1, all 4 generations of the same 24K-token prompt are admitted in the same scheduling wave, so no block is cached before its twins arrive; (b) in SWE2 multi-turn, the adapter's session-sticky routing (vllm_model/app.py:525) is keyed on an HTTP session cookie that the OpenHands client never carries, so every request round-robins to the other engine and the previous turn's KV is always on the wrong replica.

def _resolve_client(self, request: Request) -> NeMoGymAsyncOpenAI:
    session_id = request.session[SESSION_ID_KEY]
    if session_id not in self._session_id_to_client:
        # "There is probably a better way to select the endpoint..." (upstream comment)
        client_idx = len(self._session_id_to_client) % len(self._clients)  # cookie-less client lands here every call

Fix: derive stickiness from request content (hash of the first user message or metadata.instance_id) — ~10 lines in the adapter, no correctness risk (all engines hold identical weights; RL refit updates them in lockstep). Note: prefill is only 3.6% of SWE2 LLM time at this concurrency, so this fix is about GPU efficiency at scale (and about giving SpecDec a cleaner decode share), not about the small-batch latency measured here.

4. Methodology notes

  • Profiler: Gym PR #1825 + nv-OpenHands PR #19 give per-phase times (create/connect/initialize runtime, openhands_run, final eval) and per-call LLM latency records with completion timestamps. The Chrome-trace converter (swe_trace_converter.py) renders Perfetto timelines.
  • Acceptance measurement: teacher-forced replay of real trajectories against a standalone engine, reading vllm:spec_decode_num_accepted_tokens / num_drafts / per_pos counters (eager mode — acceptance is execution-mode independent).
  • Fair-baseline discipline: every claimed confound (V1 vs V2 graphs, capture sizes, paper hyperparameters) was closed with a dedicated control run; per-token throughput (tok/s) is the primary metric because temperature-1.0 trajectories diverge across variants.
  • Timestamp gotcha: trajectory event timestamps are UTC-naive while PR #19 records are UTC-aware — normalize before mixing or you will see fake 7-hour gaps.
