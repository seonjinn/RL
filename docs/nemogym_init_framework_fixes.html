NeMo-Gym SWE initialization and framework overhead

Canonical evidence page for the remaining cold-start costs in NeMo-Gym SWE rollouts. It supersedes the earlier smoke-test narrative and separates committed measurements from handoff claims and models. Companion to the broader overhead analysis.

Every quantitative claim below has one status. Measured means it is backed by a committed artifact in this worktree. Handoff-reported means it is recorded in HANDOFF_CODEX.md, but raw data or job IDs are not yet committed. 3. Code-grounded root causes

Workspace initialization: a hard-link attempt always falls back to a full copy

The entry script attempts this exact workspace setup:

if ! cp -al /testbed /workspace/$WORKSPACE_NAME 2>/dev/null; then
    cp -r /testbed /workspace/$WORKSPACE_NAME
fi

Measured The cp -al path cannot create hard links across the read-only instance squashfs and the writable workspace filesystem. It therefore fails and the script takes cp -r for every rollout. The full copy, rather than git cleanup, dominates initialization.

Measured NRL_SKIP_GIT_RESET=1 changes initialization only from 20.1 to 19.9 seconds. That null result rejects the earlier git-cleanup diagnosis; it does not make the workspace-copy cost disappear.

Framework startup: one-shot import work is paid every rollout

Measured Each rollout launches run_infer.sh, which starts a new Python process for run_infer.py. That process eagerly imports the OpenHands evaluation, agent, controller, configuration, and runtime stack before creating the runtime. The framework phase is consequently a once-per-rollout process and import cold start, not an inter-turn tax.

Action-server connection: warm globals cannot survive the process boundary

Measured LocalRuntime starts a fresh python -u -m openhands.runtime.action_execution_server process. It imports its stack, constructs ActionExecutor, and initializes bash, plugins, and environment state. The process is terminated when the rollout completes. Any warm-server globals are process-local and disappear when the one-shot run_infer.py process exits.
