NeMo-Gym SWE initialization and framework overhead

Canonical evidence page for the remaining cold-start costs in NeMo-Gym SWE rollouts. It supersedes the earlier smoke-test narrative and separates committed measurements from handoff claims and models. Companion to the broader overhead analysis.

1. Evidence status and provenance

Every quantitative claim below has one status. Committed aggregate means the worktree contains arm-level phase means and aggregate duration sums, but not per-rollout rows, pairing keys, job IDs, or elapsed-job timestamps. Handoff-reported means it is recorded in HANDOFF_CODEX.md, but its supporting artifact is not committed. Projected means it is a calculation or unvalidated hypothesis. Code-inspected means the path was read from the pinned remote checkout; that source is not vendored in this worktree.

Current decision: the n=24 aggregate ledger supports phase-level import and connect savings. It does not contain allocation-to-result timestamps, so it cannot establish a full-job speedup or regression. A complete-job comparison must include mirror setup, failures, concurrency drain, and elapsed timestamps.

3. Code-grounded root causes

Workspace initialization: a hard-link attempt always falls back to a full copy

The entry script attempts this exact workspace setup:

if ! cp -al /testbed /workspace/$WORKSPACE_NAME 2>/dev/null; then
    cp -r /testbed /workspace/$WORKSPACE_NAME
fi

Code-inspected The cp -al path cannot create hard links across the read-only instance squashfs and the writable workspace filesystem. It therefore fails and the script takes cp -r for every rollout. This explains why full copying, rather than git cleanup, dominates initialization.

Handoff-reported NRL_SKIP_GIT_RESET=1 changes initialization only from 20.1 to 19.9 seconds. Its raw timing artifact is not committed; the result nonetheless warns against prioritizing further git work.

Framework startup: one-shot import work is paid every rollout

Code-inspected Each rollout launches run_infer.sh, which starts a new Python process for run_infer.py. That process eagerly imports the OpenHands evaluation, agent, controller, configuration, and runtime stack before creating the runtime. The framework phase is consequently a once-per-rollout process and import cold start, not an inter-turn tax.

Action-server connection: warm globals cannot survive the process boundary

Code-inspected LocalRuntime starts a fresh python -u -m openhands.runtime.action_execution_server process. It imports its stack, constructs ActionExecutor, and initializes bash, plugins, and environment state. The process is terminated when the rollout completes. Any warm-server globals are process-local and disappear when the one-shot run_infer.py process exits.
